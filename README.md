# AI-агент анализа государственных закупок РК

Агент отвечает на вопросы на русском и казахском языках по данным портала goszakup.gov.kz (API OWS v3) для 27 организаций за 2024–2026 годы. Он ищет договоры, считает суммы, сравнивает цены, находит ценовые аномалии, оценивает справедливость цены лота и нетипичный рост закупаемых объёмов.

Главный принцип: **языковая модель только понимает вопрос и выбирает инструмент, а все числа считает SQL**. Поэтому каждое число в ответе можно проверить по базе, а каждый ответ заканчивается строкой, которая его воспроизводит.

| Метрика | Результат | Требование ТЗ |
|---|---|---|
| Точность извлечения фактов, типовые вопросы (30) | **99,0%** с моделью, **100%** без модели | ≥ 85% |
| Точность, свободные формулировки (10) | **97,5%** с моделью, 45% без модели | — |
| Выбор нужного инструмента | 40 из 40 | — |
| Обновление данных | инкрементально, ежедневно | ≤ 24 ч |

Подробный отчёт: [`eval/report.md`](eval/report.md).

## Быстрый старт (Docker)

Нужны Docker Desktop и токен OWS v3 (выдаётся на портале goszakup.gov.kz, раздел для разработчиков).

```bash
cp .env.example .env          # вписать OWS_TOKEN, при желании ключ языковой модели
docker compose up -d --build  # база + загрузка данных + ежедневное обновление
docker compose logs -f updater
```

Первый запуск загружает данные из API целиком, это занимает заметное время. Дальнейшие запуски догружают только изменения: около 10 минут. Когда в логах появится `обновление завершено`, можно задавать вопросы:

```bash
docker compose run --rm agent "Кому организация 990740002243 заплатила больше всего в 2025 году?"
docker compose run --rm agent "63224230-ЗЦП1 лотының бағасы әділ ме?"
docker compose run --rm agent            # интерактивный режим
```

Оценка точности внутри контейнера (отчёт сохранится в `eval/`):

```bash
docker compose run --rm --entrypoint python agent src/evaluate.py --llm
```

## Запуск без Docker

Нужны Python 3.12+ и PostgreSQL 16 (адрес базы задаётся в `DATABASE_URL`).

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

python src/ingest.py        # загрузка из API (повторный запуск — только изменения)
python src/transform.py     # витрины + отчёт о качестве данных
python src/fair_price.py    # справедливая цена
python src/ask.py "вопрос"  # вопрос агенту
```

| Команда | Что делает |
|---|---|
| `python src/ask.py --no-llm "…"` | разобрать вопрос правилами, без языковой модели |
| `python src/ask.py --json "…"` | вывести результат инструмента в JSON |
| `python src/ingest.py --full` | загрузить всё заново, игнорируя прошлые запуски |
| `python src/ingest.py --only contracts,plans` | загрузить только выбранные сущности |
| `python src/scheduler.py --once` | выполнить полное обновление один раз |
| `python src/evaluate.py [--llm]` | оценка точности на 40 вопросах |

## Языковая модель (необязательно)

Без модели агент работает на правилах: типовые вопросы он понимает полностью, свободные формулировки хуже. Модели передаётся **только текст вопроса** и описание инструментов, данные из базы в неё не уходят. Провайдер выбирается в `.env`, код менять не нужно:

| Провайдер | `LLM_PROVIDER` | Примечание |
|---|---|---|
| Claude | `anthropic` | ключ в `ANTHROPIC_API_KEY` |
| OpenAI, рассуждающие модели (gpt-6.1-sol) | `openai_responses` | `LLM_REASONING_EFFORT=low` |
| Любой OpenAI-совместимый: Gemini, DeepSeek, OpenRouter | `openai` | свой `LLM_BASE_URL` |
| Локальная модель (Ollama, vLLM) — данные не покидают сервер | `openai` | `LLM_BASE_URL=http://localhost:11434/v1` |

Готовые блоки настроек — в [`.env.example`](.env.example). Проверено на `gpt-6.1-sol`; остальные подключения проверены на имитации ответов API. Если модель недоступна, агент предупреждает строкой `[LLM: …]` и отвечает на правилах.

## Какие вопросы понимает агент

| Тип вопроса | Инструмент | Пример |
|---|---|---|
| Поиск | `search_contracts` | Покажи договоры поставщика 930340000390 |
| Аналитика | `spend_summary` | Сколько потратил заказчик 051040005150 в 2025 году по поставщикам? |
| Сравнение | `compare_prices` | Сравни цены на ЕНСТРУ 172312.700.000031 по городам |
| Аномалии цен | `price_anomalies` | Найди закупки с отклонением цены более 30% по ЕНСТРУ 841311.000.000001 |
| Справедливость цены | `fair_price_check` | Оцени справедливость цены лота 28961561-ОЛ-ЗЦП1 |
| Нетипичные объёмы | `volume_anomalies` | Есть ли необычный рост объёмов у заказчика 990740002243 в 2026 году? |

Вопросы не о госзакупках («какая погода завтра?») агент вежливо отклоняет.

Каждый ответ состоит из шести разделов ТЗ: **краткий вывод**, **использованные данные** (период, фильтры, N), **сравнение**, **метрика оценки**, **ограничения и уверенность**, **примеры Top-K** со ссылками на договоры и объявления на goszakup.gov.kz. Последняя строка — вызов инструмента с параметрами, например `spend_summary(customer_bin="990740002243", year_from=2025, year_to=2025, group_by="supplier")`.

## Как это устроено

```
API OWS v3 (GraphQL + REST)
   │  ingest.py — инкрементально по indexDate
   ▼
PostgreSQL: raw.record (сырой JSON) → таблицы plan, trd_buy, lot, contract, contract_unit, subject, справочники
   │  transform.py — очистка, единицы измерения, витрины, отчёт о качестве
   ▼
Витрины mart.*: price_fact, price_benchmark, price_deviation, volume_anomaly
   │  fair_price.py — справедливая цена (инфляция, сезон, регион)
   ▼
mart.fair_price
   │
   ▼
Агент: вопрос → модель или правила выбирают инструмент → проверка параметров → SQL → ответ по шаблону RU/KZ
```

Ежедневный цикл `ingest → transform → fair_price` запускает `scheduler.py` (сервис `updater`, 03:00 по Алматы).

**Справедливая цена (Fair Price)** — медиана цен аналогичных закупок других заказчиков: тот же код ЕНСТРУ и единица измерения, окно ±12 месяцев. Сначала ищутся аналоги в том же городе, затем в области, затем по стране. Цены приводятся к одному моменту по индексу инфляции, учитываются сезонный и региональный коэффициенты. Цена считается завышенной, если она выше справедливой более чем на 30% и выходит за Q3 + 1,5·IQR. Отличие в 10 раз и больше считается вероятной ошибкой ввода.

Подробное описание архитектуры, схемы хранения, методов и рисков — в папке [`docs/`](docs/).

## Безопасность

- Токены и ключи хранятся только в `.env`: он исключён из Git (`.gitignore`) и из Docker-образа (`.dockerignore`).
- База доступна только с локального компьютера (`127.0.0.1:5433`).
- Агент подключается к базе в режиме только для чтения.
- Контейнеры работают не от root.
- Языковой модели передаётся только текст вопроса; возможен полностью локальный режим.

## Структура проекта

```
├── src/
│   ├── ingest.py          загрузка из OWS v3 (GraphQL, REST-справочники)
│   ├── transform.py       витрины и отчёт о качестве данных
│   ├── fair_price.py      справедливая цена
│   ├── scheduler.py       ежедневное обновление
│   ├── ask.py             вопрос агенту из командной строки
│   ├── evaluate.py        оценка точности
│   ├── agent/
│   │   ├── agent.py       основной цикл: вопрос → инструмент → ответ
│   │   ├── router.py      правила разбора и проверка параметров
│   │   ├── llm.py         подключение к языковым моделям
│   │   ├── tools.py       шесть инструментов (SQL)
│   │   ├── render.py      сборка ответа по структуре ТЗ
│   │   ├── texts.py       тексты ответов на RU и KZ
│   │   ├── db.py          подключение к базе (только чтение)
│   │   └── settings.py    пороги и настройки
│   ├── explore*.py, probe_*.py   разовые скрипты изучения API (см. ниже)
├── sql/
│   ├── schema.sql         схема хранения
│   └── marts.sql          аналитические витрины
├── eval/                  вопросы, эталоны и отчёт о точности
├── data/reference/        индекс потребительских цен (инфляция)
├── docs/                  документация для сдачи
├── bins.py                27 организаций
├── Dockerfile, docker-compose.yml, .env.example
```

**Изучение API.** Скрипты `explore.py`, `explore_details.py` и `probe_*.py` — разовые: ими изучалась структура OWS v3 перед проектированием схемы (объёмы записей по БИН, пагинация, фильтр `indexDate` для инкрементальной загрузки, REST-справочники, статусы). Для работы системы они не нужны. Исключение — `explore.py`: в нём лежат общие функции работы с API (`graphql`, `make_session`, `load_token`), которые использует `ingest.py`.

## Ограничения

Кратко (полный список — в `docs/`):

- Поиск по словам работает по русским названиям товаров; казахские названия переводит языковая модель.
- Для 53% позиций не хватает аналогов для оценки справедливой цены — агент прямо сообщает «недостаточно данных».
- Под одним кодом ЕНСТРУ иногда находятся разные товары, это снижает точность сравнения цен.
- Город поставки из плана известен для 39% позиций, для остальных берётся адрес заказчика.
- История данных начинается с 2024 года, поэтому для оценки роста объёмов доступно не больше двух прошлых лет.
- При свободной формулировке вопроса о росте объёмов модель может выбрать порог роста сама (1 из 30 типовых и 1 из 10 свободных вопросов).
- Обновление выполняется раз в сутки, поэтому данные отстают от портала не более чем примерно на 24 часа.
